# UI Information Hierarchy — 2026-09-15

Scope: make the existing portfolio application easier to explore while preserving its search, account, collection, and AI interfaces. This is an information hierarchy adjustment, not a new product workflow.

## Display Decisions

| Directly visible | Available on demand | Removed from the default view |
| --- | --- | --- |
| Search, primary examples, applied conditions, matching games, selected price/rating, saving | Advanced filters, extra examples, parsed search intent and provider explanation | Raw JSON and duplicated result/saved counters |
| Current data mode and where saves are stored | Data & setup mode switch and implementation details | Large mode-description card |
| One game recommendation with source and metadata disclosure | More game signals and catalog commentary | Large decorative stock image and prominent Strong/Watch signal |
| Account controls, collection actions, empty state, failures/retries | Collection insights when games have been saved | Empty collection analytics and default-view revenue totals |

Developer analysis remains available, with estimates labelled. The current insights use catalog metadata and aggregate values, not review source text. The provider outputs and game/collection insight endpoints are retained; the UI changes where supporting detail appears.

The primary flow now occupies the main area, with account/collections beside it on desktop. At narrow widths, discovery precedes the sidebar. Native `details` controls provide disclosure state and keyboard behavior, and visible focus outlines identify interactive controls. The search input has a visible associated label. View and selected-game buttons expose their pressed state.

The requested `ui-ux-pro-max` skill informed content priority, labelling, contrast, and narrow-screen checks. Two targeted disclosure searches returned unrelated results, so disclosure choices use the skill's built-in Forms & Feedback and content-priority guidance, not a claimed database match.

## Follow-up: Gaming Visual Direction

The user approved game-specific imagery, compact search, a tighter collection layout, and a more prominent insight conclusion, with a stronger gaming character. This subsequent pass replaces the light presentation with charcoal surfaces, lime actions, and a cyan-accented insight panel. It retains the earlier progressive disclosure and all account, collection, search, and AI behavior.

- A full-width selected-game banner shows the game's own artwork, title, summary, developer/year, catalog rating, price, and save action. Result rows include thumbnails. Twenty-four official store headers are local assets (1,189,326 bytes total); title matching avoids dependence on database IDs. Unknown artwork and failed loads have a neutral fallback. See [sources](game-artwork-sources.md).
- Search has a compact label/hint row and input, followed by examples and a combined applied-filter/disclosure toolbar. Expanded filters and diagnostics remain in document flow.
- Collections are composed below game insights in the result-side rail instead of reserving a full-height column beside search. Narrow layouts stack these panels after results.
- The insight conclusion is emphasized; the source remains visible and the metadata basis follows the conclusion. No paid AI calls, backend changes, or sample-metric refresh were made in this pass.
- The skill's gaming design-system query matched gaming typography, dark colors, and immersive artwork. This implementation uses those directional ideas with system fonts and local images; it does not add WebGL, animation libraries, or marketing-page sections from the generic recommendation.
