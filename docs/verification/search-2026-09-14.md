# Search Reliability Verification — 2026-09-14

Scope: title and condition search, consistent rules behavior in demo/API modes, and result/detail consistency during overlapping requests. This iteration retains the existing DeepSeek search and game/collection insight interfaces.

## Reproduction Before the Fix

- `Celeste` and an unknown title produced the same unrestricted intent apart from an implicit $70 ceiling. The SQL search did not filter the game name.
- `under 20.99` became a $20 limit. Ranking without an explicit budget silently excluded games above $70.
- UI regressions reproduced three failures: a newer search could not start while the previous request was pending (success and error cases), and a filter that removed Celeste left its detail heading visible.
- The existing empty-response handling already rejected late game insights. That behavior is retained and covered alongside the new regressions.

## Search Contract

`titleQuery` is a nullable, normalized literal title fragment. It combines with price, tags, rating, and review requirements using AND. SQL escapes wildcard characters so `%` and `_` remain literal, matching browser substring filtering.

`maxPrice: null` means no budget constraint; explicit decimal budgets retain their precision. Known full titles and quoted titles are extracted before interpreting genre or ranking words. Unknown text remains a literal title constraint, so it produces an empty result when no catalog name matches. Blank input produces the unrestricted catalog. The rules parser supports a bounded vocabulary, not arbitrary natural language; quote titles containing ambiguous search terms.

The UI accepts a different search while a request is pending, deduplicates the same pending query, and only applies the newest response. A subsequent manual filter also invalidates pending search responses. Selection follows the resulting game list; an empty list clears detail and insight content.
